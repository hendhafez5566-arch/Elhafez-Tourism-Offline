# Architecture boundaries and ratchet

Future direction: UI → Application/use cases → Domain/business rules → Repository interfaces → Persistence/infrastructure. No production layer migration in Phase 1.

ARCH001: DB identifier references in presentation files. ARCH002: UI/Pages/Forms/Print/toast references in persistence and domain/core files. ARCH003: Auth references except src/security/** and src/bootstrap.ts. ARCH004: assignment/compound assignment/increment/decrement/delete of UI/DB/Auth members, plus Object.assign/defineProperty/defineProperties and Reflect.set/defineProperty/deleteProperty targeting those globals. ARCH005: corresponding window/globalThis mutations in src/**. ARCH006: upward named-global dependencies; persistence to Accounting/Commercial/CRM/UmrahCore_Ops/Actions/UI/Pages/Forms/Print/toast, domain/core to Actions/CommercialActions/UIDelegatedActions/UI/Pages/Forms/Print/toast. Overlap of ARCH002 and ARCH006 is intentional. Ordinary window reads and as-any casts are not ARCH004/ARCH006.

Classifier: src/ui/** and files ending pages/forms/forms-contracts/view/actions-print.ts plus core/umrah/ui.ts are presentation; src/persistence/** persistence; security/** security; accounting/finance/core otherwise domain-core; bootstrap exempt auth location; other source application/platform. Mixed-purpose legacy files remain classified by this explicit convention. Full implementation is in scripts/architecture-check.mjs, with actual evidence/signatures in architecture-baseline.json.

Read-only AST scanner uses TypeScript syntax, excludes comments and string contents from identifier references, and hashes printer-normalized occurrence nodes without line numbers. Multiset matching keys rule + file + signature; repeated identical findings retain multiplicity. Thus new files, increased existing-file counts, new patches and same-count replacement by a different occurrence are rejected; unchanged findings and removals pass. No automatic baseline rewrite.

Limitations: module none and manual ordering preclude a complete import graph; this measures named global syntax, not runtime reachability. It is not symbol-resolved: shadowed identifiers can be false positives; aliases, computed global names, mutations through indirect references/destructuring and arbitrary helper methods can evade detection. Properties inside DB.data are counted under public-member mutation even when they are normal state writes, so ARCH004 is intentionally conservative rather than a claim that every finding is an unsafe patch. Classification of mixed core/Umrah renderers is incomplete. Signature context may flag a benign expression edit; manually review rather than automatically refresh baseline. Server imports are inventoried but rules target legacy src globals, not an exhaustive server architectural graph.
